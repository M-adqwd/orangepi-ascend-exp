## 1. 总览

| 实验 | 任务 | 输入 | 模型 | ONNX | OM | 核心指标 | 延迟 |
|---|---|---|---|---|---|---|---|
| 一 | 信用卡欺诈检测 | `split_test.npz` 56,961×29 | MLP 29-64-32-1 | 16 KB | **57 KB** | AUPRC **0.7764** / ROC-AUC **0.9710** | **0.207 ms**/条 |
| 二 | 肺炎 X 光分类 | `test/*.jpg` 624 张 | EfficientNet-B0 | 16.0 MB | **14.6 MB** | AUPRC **0.8762** / ROC-AUC **0.8452** | **7.17 ms**/张 |

## 2. 实验一 · 信用卡欺诈 MLP

**数据集**：Kaggle ULB creditcard，284,807 笔交易、29 特征（V1–V28 + Amount）、492 笔欺诈（0.17%）。

| 切分 | 样本数 | 正例 |
|---|---|---|
| train | 182,277 | 315 |
| val | 45,569 | 79 |
| test | 56,961 | 98 |

**部署链路**
1. 原包 `mlp_fraud.onnx` 仅 6.6 KB —— 权重存成了**外部文件** `mlp_fraud.onnx.data`，未随包提供，ATC 报 `Failed to get real path`。
2. 板上 `torch.onnx.export` 对单输出 Linear 触发 oneDNN `matmul primitive descriptor` 错误，关 MKLDNN 无效。
3. 改为用 `onnx.helper` **按权重手工构图**（`build_onnx_mlp.py`），`ReferenceEvaluator` 自校验与 numpy 结果 **diff = 0**，产出 `mlp_fraud_inline.onnx` 16 KB。
4. ATC：`--input_shape=input:1,29 --soc_version=Ascend310B4` → `mlp_fraud.om` 57 KB。

**结果（56,961 条全量）**

| 指标 | 基线 | 板端 OM |
|---|---|---|
| AUPRC | 0.7541 | **0.7764** |
| ROC-AUC | 0.9710 | **0.9710** |
| precision @0.99 | 0.789 | **0.798** |
| recall @0.99 | 0.765 | **0.765** |
| F1 @0.99 | — | **0.781** |

TP 75 / FP 19 / FN 23 / TN 56,844，accuracy 0.99926。
全量耗时 **12.7 秒**，单条 **0.207 ms**（p99 0.295），吞吐 **4,497 条/秒**，模型加载 1.24 s。

## 3. 实验二 · 肺炎 X 光 CNN

**数据集**：`chest_xray` 测试集 624 张（PNEUMONIA 390 / NORMAL 234）。

**部署链路**
1. `cnn_pneumonia_efficientnet_b0.onnx` 只有 659 KB，同样是外部权重引用。
2. 用原脚本 `export_onnx_pneumonia.py` 从 `efficientnet_b0_best.pth`（16.3 MB）重导为 `cnn_inline.onnx`（16.0 MB，权重内联）；脚本末尾 onnxruntime 自检因缺包报错，但导出已完成。
3. ATC：`--input_shape=input:1,3,224,224 --soc_version=Ascend310B4` → `cnn_pneumonia_b0.om` 14.6 MB。

**结果（624 张）**

| 指标 | 基线 | 板端 OM |
|---|---|---|
| AUPRC | 0.8775 | **0.8762** |
| ROC-AUC | 0.8467 | **0.8452** |
| F1 @logit 0.97 | 0.8396 | **0.8378** |
| 单张延迟 | 8.54 ms（ONNX CPU） | **7.17 ms** |

> **阈值语义坑（重要）**
> 基线 `eval_baseline.py` 用的是 `logits[1] - logits[0]` 的**原始 logit 差值**（无界，可 > 1），不是概率。
> 若误当概率卡 0.97：softmax 后 TP 仅 5、FN 385，F1 塌到 0.025。
> 按同一尺度复算，OM 在 0.97 处 TP 390 / FP 151 / FN 0 / TN 83，F1 0.838 vs 基线 0.840 —— **只差 2 张图，数值等价成立**。
> 逐图得分已存 `scores.npz`，扫描后 logit 尺度最佳 F1 **0.8735 @1.623**（等价 softmax 0.85）。

## 4. 实验三 · YOLOv8n 人员检测

**输入**：COCO 预训练 `yolov8n.pt`（6.5 MB，3.2M 参数），不做重训，只取 person 类。

**部署链路**
1. `yolov8n.onnx` 12.9 MB（权重完整），输出 `[1, 84, 8400]`。
2. ATC：`--input_shape=images:1,3,640,640 --soc_version=Ascend310B4` → `yolov8n.om` 7.2 MB。
3. 原 `infer_yolov8_ascend.py` 的手写 pyACL 绑定与板上版本不兼容（`acl.RT_MEMCPY_HOST_TO_DEVICE` 不存在、`numpy_to_ptr` 已废弃），改用 `InferSession` 重写。

**结果**

| 场景 | 结果 |
|---|---|
| 静态图 `bus.jpg` | 检出 **4 人**（标准答案 4 人），score 0.890 / 0.883 / 0.878 / 0.434 |
| 静态图延迟 | 25.9 ms（p99 26.2） |
| USB 摄像头 120 帧 | 全部处理，只框人、无误框 |
| 纯推理 | **26.4 ms → 37.8 FPS** |
| 端到端 | 62.5 ms → 16.0 FPS（含采集 + letterbox + 解码 + 绘图） |

> 端到端掉到 16 FPS 是 Python 侧串行开销，NPU 仍有 37.8 FPS 余量；多线程取帧可再提升。

**实时预览**：板端 `cam_stream_server.py` 提供 MJPEG 服务，浏览器打开 `http://192.168.8.199:8000` 即可看带框画面。

## 5. 数据流规格（交接点）

| 实验 | 环节 | 数据 | 形状 / dtype | 字节 |
|---|---|---|---|---|
| 一 | 输入 | `split_test.npz` X | `[56961, 29]` f32 | 6.1 MB |
| 一 | 预处理后 | 单条样本 | `[1, 29]` f32 | 116 B |
| 一 | 模型输出 | logit | `[1, 1]` f32 | 4 B |
| 二 | 输入 | JPEG | `3×224×224` uint8 | ≈150 KB/张 |
| 二 | 预处理后 | NCHW | `[1,3,224,224]` f32 | 602,112 B |
| 二 | 模型输出 | 2 类 logits | `[1, 2]` f32 | 8 B |
| 三 | 输入 | 视频帧 | `1280×720×3` uint8 | 2.64 MB |
| 三 | 预处理后 | letterbox NCHW | `[1,3,640,640]` f32 | 4,915,200 B |
| 三 | 模型输出 | 3 尺度拼接 | `[1,84,8400]` f32 | 2,822,400 B |

输入字节量：116 B → 602 KB → 4.9 MB，跨约 4 个数量级，与延迟量级（0.2 / 7 / 26 ms）正相关。

## 6. 踩过的坑（8 项）

| # | 问题 | 影响 | 处理 |
|---|---|---|---|
| 1 | `exp1`/`exp2` 的 ONNX 引用外部权重 `.onnx.data`，未随包提供 | ATC 直接失败 | 分别用 `onnx.helper` 手工构图 / 原脚本重导，产出权重内联版 |
| 2 | `infer_mlp_ascend.py --all-test` 每条样本起一次 ais_bench 子进程 | 56,962 次 ≈ 16 小时 | 改用 `InferSession` 只加载一次，全量 12.7 s |
| 3 | 手册写 `latest/setenv.sh`，实际为 `ascend-toolkit/set_env.sh` | 环境变量未生效 | 更正路径 |
| 4 | `ais_bench` CLI 参数名与脚本不一致（`--output_size` vs `--outputSize`），且未进 PATH | `which ais_bench` 失败 | 建 `~/exp/bin/ais_bench` wrapper |
| 5 | 初期无 USB 摄像头；`/dev/video0/1` 为 MIPI multiplanar，不支持 MJPG | 摄像头验收受阻 | 接入 USB UVC 后识别为 `/dev/video2` |
| 6 | aarch64 上 `torch.onnx.export` 触发 oneDNN matmul 错误 | 实验一无法重导 | 改手工构图，diff = 0 |
| 7 | `ais_bench 0.0.2` 的 `InferSession` 无 `free_resource` | 退出报 AttributeError | try/except 兜底 |
| 8 | `infer_yolov8_ascend.py` 的 pyACL 绑定与板上版本不兼容 | 摄像头循环崩溃 | 用 `InferSession` 重写 `cam_detect_yolo.py` / `cam_stream_server.py` |

**另外两个环境事实**：`bash -lc` 不读 `~/.bashrc`，需手动把 miniconda 放回 PATH；Git Bash 会把 `/home/...` 参数做 MSYS 路径转换，传远端路径要用 PowerShell。

## 8. 复现命令（板端）

```bash
source /usr/local/Ascend/ascend-toolkit/set_env.sh
export PATH=/usr/local/miniconda3/bin:$HOME/exp/bin:$PATH
export TE_PARALLEL_COMPILER=1 MAX_COMPILE_CORE_NUMBER=1

    --test-dir data/chest_xray/test --threshold 0.5 --scores-out scores.npz --out om_test_metrics.json

# 实验三（静态图 / 摄像头 / 网页直播）

cd ~/exp/exp3 && python3 cam_detect_yolo.py --om yolov8n.om --device /dev/video2 --max-frames 120
cd ~/exp/exp3 && setsid nohup python3 cam_stream_server.py --om yolov8n.om --device /dev/video2 --port 8000 &
```

## 9. 遗留

1. RKNN / RK3588S 侧未验证（无对应板卡）。
2. 摄像头端到端 16 FPS 受 Python 串行限制，可多线程取帧提升。
3. NPU `npu-smi` 健康状态仍为 Alarm（`80E3A203` LPM 电流异常 / `80F18003` DDRA 配置错误），属板级传感器/配置层面，不影响本次全部计算。
4. MIPI 摄像头需单独配置 ISP pipeline 与权限，不能复用 UVC 的 MJPG 路径。
